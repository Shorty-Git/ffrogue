## Fourth module array: discovered gate, not an implicit mode

Null AssignModule/GetModuleCount take a fourth unsigned-byte argument. Static
inspection of original Null Initialize shows its value passed at0x1fbce28 from
a derived inherited flag (shift at0x1fbd094). The follow-up below proves its
bounded arithmetic, but does not replay the actual source child constructors.
The tool therefore requires an explicit `--auxiliary-flag 0|1`; it does not infer
a runtime mode from the filename, source availability or a similarly named asset.

With flag1, the original assigner fills a **fourth module array** with3/4/3/3
callbacks for nodes0/1/5/7. Native symbols identify these as `delta_zero_update`
scaling, rotation, translation and locator functions. Original code at
0x1fc1410..0x1fc15a8 writes through ModuleArray +0x18. The first exploratory
three-array harness hit the original capacity assertion at0x1fc15b4; this was
traced to the missing fourth descriptor, not bypassed by choosing flag0.

The shared reference now allocates/reads all four descriptors, checks **all four**
native counts and retains `auxiliaryModules`. Probe requests requiring that
additional array return an explicit blocked result; they never run an incomplete
three-array chain. Flag0 is the declared fixture for the currently executed
chains, not a claim about the game's required mode. Wiring delta-zero updates,
their timing/context and the selector derivation is part of the remaining
nested-generation/inheritance work.
